## Configuration

| setting | value |
|---|---|
| servers | `c9g.16xlarge` 64 vCPU arm64, one per lane, four lanes |
| clients | `m9g.8xlarge`, 32 vCPU, one per lane, same availability zone |
| models | 10M and 20M, FP32, ONNX |
| wire | 210 named features per row, transformed and concatenated by hushar into the model's one 690-float input; server-side vectorization ON |
| feature logging | `inference_log.sample_rate` 0.2 -> 1 request in 5, to Amazon S3 |
| log object | one per 50,000 logged rows -- 500 requests at 100 rows, 100 requests at 500 rows; 0 cell(s) with write failures and 1 that shed |
| candidate model | none; every request scores the one resident model |
| mini batch | `mini_batch_size` in rows, the primary axis. The size equal to the row count is one engine call per request |
| parallelism | `threading.sessions_per_model` 8 and 4 (requests scored at once), `sessions_per_request` 1, so a request's mini batches share its one session |
| intra-op width | 8 session(s) x 8 thread(s), 4 session(s) x 16 thread(s) = 64 either way |
| per-session concurrency | `threading.concurrency_per_session` 64, held constant, so every cell's mini batches overlap and the size is the only variable in a group |
| spinning | `threading.allow_spinning` false; idle threads sleep |
| engine | ONNX Runtime 1.28.0, CPU provider, official CPU-only build |
| window | 900s measured in 15 slices, after a 300s warm-up discarded; fresh server per cell, 60s idle between |
| cells | 56 measured, 55 sustained the offered rate |
